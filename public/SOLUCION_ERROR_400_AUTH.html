🔧 Solución: Error 400 en Autenticación

Guía paso a paso para resolver el error de autenticación en Supabase

❌ Error Identificado

La consola muestra el siguiente error:

Failed to load resource: the server responded with a status of 400 ()
/auth/v1/token?grant_type=password

Causa: La autenticación por email/password no está configurada correctamente en Supabase, o los usuarios no existen en el sistema de autenticación.

1

Habilitar Autenticación por Email en Supabase

Primero debes habilitar la autenticación por email en Supabase:

  1. Ve a Supabase Dashboard → Authentication → Providers
  2. Busca Email en la lista de proveedores
  3. Asegúrate de que esté habilitado (toggle activado)
  4. Configura las opciones:
    • ✅ Enable Email provider: Activado
    • ❌ Confirm email: Desactivado (para pruebas)
  5. Haz clic en Save
2

Crear Usuarios en Supabase Auth

Debes crear los usuarios en el sistema de autenticación de Supabase:

  4. ✅ Marca "Auto Confirm User"

3

Ejecutar Script SQL para Crear Perfiles

Después de crear los usuarios en Auth, necesitas crear sus perfiles en la tabla users:

  1. Descarga el script: 📥 Descargar fix-auth.sql
  2. Abre el SQL Editor: 🔗 Ir al SQL Editor
  3. Copia y pega TODO el contenido del script
  4. Haz clic en "Run" (o Ctrl+Enter)

Este script:

  • Verifica que los usuarios existan en auth.users
  • Crea los perfiles en la tabla users
  • Asigna los roles correctos (admin/teacher)
  • Verifica que los emails estén confirmados
4

Verificar la Configuración

Ejecuta esta consulta en el SQL Editor para verificar que todo esté correcto:

SELECT
  u.email,
  u.name,
  u.role,
  u.active,
  a.email_confirmed_at
FROM users u
LEFT JOIN auth.users a ON u.id = a.id;

Deberías ver:

  • ✅ Los usuarios con sus roles correctos
  • ✅ email_confirmed_at no es NULL
  • ✅ active = true
5

Probar la Autenticación

Ahora puedes intentar iniciar sesión en la aplicación:

  1. Recarga la aplicación con Ctrl+F5
  2. Ve a la página de login
  3. Ingresa las credenciales:

    Password: Admin2026!

  5. Deberías ver el Dashboard con acceso completo de administrador

✅ Checklist de Verificación

⚠️ Si el Error Persiste:
  • Verifica la consola del navegador (F12) para ver errores específicos
  • Revisa la pestaña Network para ver la respuesta detallada del servidor
  • Asegúrate de que las credenciales sean correctas
  • Verifica que el usuario exista en auth.users y en la tabla users
✅ Otros Errores en la Consola:
  • WebSocket errors: Son normales en desarrollo, no afectan la funcionalidad
  • React Router warnings: Son advertencias de futuras versiones, no afectan la funcionalidad
  • SVG path errors: Son errores de renderizado de iconos, no críticos
