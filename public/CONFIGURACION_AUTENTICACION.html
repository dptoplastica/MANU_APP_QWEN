🔐 Configuración de Autenticación

Guía completa para configurar y usar el sistema de autenticación

⚠️ Problema Identificado

La consola muestra el error 400 (Bad Request) en /auth/v1/token?grant_type=password. Esto indica que la autenticación de Supabase no está configurada correctamente.

Solución: La aplicación ahora funciona en MODO LOCAL como fallback, pero para persistencia completa necesitas configurar Supabase Auth.

📦 Modo Local vs Modo Supabase

Modo Local: La aplicación funciona con datos de demostración. Los cambios NO se persisten en Supabase. Útil para pruebas rápidas.

Modo Supabase: La aplicación usa Supabase Auth y persiste todos los datos en la base de datos. Requiere configuración adicional.

Configurar Supabase Auth (Para Persistencia)

Para que los datos se persistan en Supabase, necesitas:

  1. Habilitar Email Provider:
    Ir a Authentication → Providers
    • Busca Email en la lista
    • ✅ Activa Enable Email provider
    • ❌ Desactiva Confirm email (para pruebas)
    • Haz clic en Save
  2. Crear Usuarios en Supabase Auth:
    Ir a Authentication → Users
    • Haz clic en "Add user" → "Create new user"
    • Crea el usuario administrador:
      Email: admin@ieslopedevega.es
      Password: Admin2026!
      ✓ Auto Confirm User
    • Crea el usuario profesor:
      Email: profesor@ieslopedevega.es
      Password: Prof2026!
      ✓ Auto Confirm User

Ejecutar Script SQL para Crear Perfiles

Después de crear los usuarios en Supabase Auth, necesitas crear sus perfiles en la tabla users:

  1. Descarga el script: 📥 Descargar fix-auth.sql
  2. Ejecuta en Supabase: 🔗 Ir al SQL Editor

  3. Copia y pega el contenido del script y haz clic en "Run"

4

Verificar la Configuración

Ejecuta esta consulta en el SQL Editor para verificar:

SELECT
  u.email,
  u.name,
  u.role,
  u.active,
  a.email_confirmed_at
FROM users u
LEFT JOIN auth.users a ON u.id = a.id;

Deberías ver:

  • ✅ Los usuarios con sus roles correctos
  • ✅ email_confirmed_at no es NULL
  • ✅ active = true
5

Probar la Autenticación con Supabase

Después de configurar Supabase Auth:

  1. Recarga la aplicación con Ctrl+F5
  2. Inicia sesión con las mismas credenciales
  3. Verás un mensaje diferente en la consola:
    🌐 ✅ Sesión iniciada con Supabase
    🌐 Los datos se persisten en Supabase

✅ Resultado Esperado

Modo Local: La aplicación funciona inmediatamente con datos de demostración. Los cambios se pierden al recargar.

Modo Supabase: La aplicación persiste todos los datos en Supabase. Los cambios se mantienen entre sesiones.

🔍 Diagnóstico de Problemas

Si ves el error 400: Supabase Auth no está configurado. Usa el modo local o configura Supabase Auth siguiendo los pasos anteriores.

Si el login falla: Verifica que las credenciales sean correctas y que el usuario exista en Supabase Auth (si usas modo Supabase).

Si los datos no se persisten: Verifica que estás en modo Supabase (revisa la consola del navegador).
